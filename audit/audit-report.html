Critical DEV-1

SSH connection cache bypasses authentication for shared (host, port, username) keys

#733
fleet_platform/services/ssh_connection_cache.py:61-80; fleet_platform/api/routes/webssh.py:339-356
key = (host, port, username); if key in _cache: return cached.conn  # returned without any credential check
Impact

Cache key omits credentials. If user A opens a key-auth session to node1:22:admin, user B requesting the same (host, port, username) — even with a wrong key/password — receives A's live connection. Authentication is fully bypassed on every cache hit, enabling lateral access to any node another user recently connected to using only the correct username.

Fix

Include a credential fingerprint in the cache key (HMAC of the public key bytes / KDF of the password) or scope the key to (host, port, username, user_id) so connections are never shared across credentials/users.

#735
fleet_platform/services/agent_apply_svc.py:100-128

poll_salt_masters runs asyncio.run() per master in a serial loop

#734
fleet_platform/workers/maintenance.py:294-316

Medium DEV-11

SSH probe writes private key to a temp file without chmod 0600, so OpenSSH rejects it

#743
fleet_platform/workers/connectivity_tasks.py:71-88
with tempfile.NamedTemporaryFile(...) as tmp: tmp.write(ssh_key); tmp.flush(); subprocess.run(['ssh', ..., '-i', tmp.name, ...])  # no chmod
Impact

NamedTemporaryFile applies the process umask (often 0644/0640). OpenSSH rejects group/other-readable key files (rc=1), so every key-auth probe falsely classifies the node as unreachable, making reachability data unreliable.

Fix

Add os.chmod(tmp.name, 0o600) immediately after tmp.flush() and before subprocess.run.
