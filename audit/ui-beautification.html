Executive summary

A cohesive enterprise design system for kri

kri today is a capable fleet-ops console with solid bones — a dark indigo shell, white card surfaces, and a sensible brand scale. But the visual language drifts page-to-page: four different StatusBadge definitions, emoji mixed with Unicode glyphs, four radius values, and sparse empty/loading states. This proposal codifies one token system — "Cobalt Ops" — derived from the existing brand indigo, then shows every page rebuilt against it.

Every mockup on every tab below is rendered live from the same CSS variables defined once at the top of this file. Toggle light/dark in the header to see the whole system re-theme instantly — that is exactly the portability the app should adopt.

1 Top five cross-cutting recommendations

Priority 01
Tokenize everything
Replace hard-coded hex (#F9FAFB, #0f0f23) and the 4 ad-hoc status palettes with CSS variables + a Tailwind theme. One source of truth → instant dark mode & density modes.
Priority 02
One icon language
Retire emoji (🔴 📊 🛡️) and Unicode glyphs (⊞ ◑ ▷) for a single line-icon set (Lucide). Consistent stroke, size, and optical weight across nav, badges, and buttons.
Priority 03
A real type scale
Adopt a display/body/mono pairing (Archivo · IBM Plex Sans · IBM Plex Mono) and a fixed modular scale. Numbers get tabular figures everywhere they're compared.
Priority 04
First-class states
Upgrade the bare ErrorState, gray-bar Skeleton, and missing empty states into a designed family: illustrated empties, content-shaped skeletons, actionable errors.
Priority 05
Density & accessibility as settings
Ship a comfortable/compact density toggle for data-dense tables, and bring contrast, focus rings, and hit-targets to WCAG AA. Today text-gray-400 on white and white/35 on the login both fail AA for body text.

Navigation hub

Overview Hub

Top-level shell (HubPage.tsx) that hosts Fleet Overview, Fleet, Fleet Health, Groups and Salt Masters as in-page tabs. The single most reused chrome in the app — so its polish multiplies everywhere.

1 Current-state critique

Tab bar uses negative-margin hacks

-mx-6 -mt-6 to break out of main's padding is fragile and couples the hub to the layout's exact spacing.

Glyph icons (⊞ ⬡ ♥ ◫ ◆) read as mojibake

Font-dependent Unicode symbols render inconsistently across OSes and look unintentional next to real UI.

Active state is colour-only

Brand text + 2px underline is the sole affordance; no count/summary context per tab, and contrast is borderline for the inactive gray-500 labels.

No overflow strategy

Five tabs fit today, but there's no scroll/condense behaviour as hubs grow (Compliance already has seven).

2 Enterprise recommendations

P1
Standardize a Tabs primitive with line-icon + label + optional count chip, sticky, with horizontal scroll-snap and a gradient fade at edges on overflow.
P1
Replace glyphs with Lucide icons sized 16px, inherited stroke, aligned to the text baseline.
P2
Add per-tab live counts (e.g. nodes, pending masters) so the hub doubles as a status glance.
P2
Keyboard + ARIA: role="tablist", arrow-key navigation, visible focus ring.

Navigation hub

Compliance Hub

Hosts Drift, Baselines, SBOM, Licenses, Security, Alerts and Config Profiles. Seven tabs of compliance posture — the page that auditors and security leads live in.

1 Current-state critique

Seven tabs, no posture summary

The hub jumps straight into Drift with no roll-up of overall compliance health — users must visit each tab to assess risk.

Glyph soup in tabs

◑ ▬ ◉ ⚖ ⛨ ◭ ⚙ are visually noisy and semantically opaque.

No severity signalling on the nav

A tab with 12 critical CVEs looks identical to a clean one — risk is hidden until you click.

Inconsistent child layouts

Each child page sets its own heading, padding and stat-card style, so switching tabs feels like switching apps.

2 Enterprise recommendations

P1
Add a posture ribbon above the tabs: a compact risk score + counts (critical/high CVEs, drifted nodes, license risks) that turns the hub into a dashboard.
P1
Surface severity on tabs with a coloured count badge driven by the worst finding in each domain.
P2
Normalize child page chrome — shared page header, stat-card row, and table component so all seven feel like one product.
P2
Export action in the hub header (PDF/CSV compliance report) — a frequent ask for this audience.

Automation Hub

Executions, Playbooks, Provisioning, Salt Ops and Minion Keys. Fires a background git-pull of playbook sources on mount and surfaces a bottom-right sync toast.

1 Current-state critique

Sync toast is bespoke

The fixed bottom-right banner is hand-rolled with its own transition rather than the app's ToastContainer, creating two toast systems.

Background sync is invisible until done

Users can click Playbooks mid-pull and see stale data with no inline "refreshing" indicator on the list.

Minion Keys badge is the only signal

Pending keys show an amber count, but other actionable states (failed executions) get no nav signalling.

No primary action in hub header

"Run playbook" — the hub's main job — lives one tab deep instead of being a persistent CTA.

2 Enterprise recommendations

P1
Consolidate on one toast system with status variants (syncing/success/error) and a queue.
P1
Persistent "Run playbook" CTA in the hub header, available from any tab.
P2
Inline sync state: a subtle "Syncing sources…" pill on the Playbooks tab while the pull runs.
P2
Badge failures & running jobs on Executions so the hub reflects live ops at a glance.

Fleet & nodes

Fleet Overview

The landing dashboard: clickable stat cards (nodes, drift, vulnerabilities), a fleet status bar, and recent-activity rollups. First impression of the entire product.

1 Current-state critique

Cards are visually flat & uniform

border-l-4 + text-4xl font-black on every card gives no hierarchy — a critical CVE count looks the same weight as total nodes.

No trend / delta context

Numbers are point-in-time; there's no sparkline or "+12 since yesterday" to make them actionable.

Status bar lacks legend & AA contrast

The thin segmented bar relies on hover titles; text-gray-500 labels are low-contrast.

font-black is too heavy

900-weight numerals at 4xl feel shouty; a display 800 with tabular figures reads more premium.

2 Enterprise recommendations

P1
Hierarchy by intent: a hero metric, supporting metrics, and a risk metric that escalates colour only when non-zero.
P1
Add micro-trends — inline sparkline + delta chip per card.
P2
Legend + accessible status bar with labelled segments and tabular counts.
P2
Skeletons that match the card grid, not generic gray bars.

Fleet & nodes

Fleet (Nodes)

The master nodes table — status, drift, OS, last-seen — with bootstrap, import, edit modals and pagination. The operational workhorse view.

1 Current-state critique

High-density table, low scannability

Uniform row weight and gray text make it hard to triage which nodes need attention; no row-level emphasis for offline/drifted.

Actions buried per-row

Bootstrap/Edit live inline without a consistent overflow menu; bulk operations aren't obvious.

No sticky header on long lists

Scrolling 50 rows loses the column context.

Filter affordances are minimal

Status filtering exists but there's no chip-based active-filter display or saved views.

2 Enterprise recommendations

P1
Triage-first table: sticky header, hover row tint, monospaced IDs, and a leading status dot column.
P1
Row selection + bulk action bar that slides in with count and primary actions.
P2
Filter chips + saved views above the table; per-column sort indicators.
P2
Density toggle (comfortable/compact) persisted per user.

Fleet Health

Per-node health snapshots — CPU, memory, disk, thermal, uptime, power — as a card grid with alert highlighting and historical line charts (recharts).

1 Current-state critique

Alert cards use red fill + red border

The whole card going bg-red-50 border-red-400 is heavy; a focused indicator would be calmer and clearer.

Metric bars lack thresholds & labels

Bars switch green→yellow→red but show no numeric value or threshold marker inline.

Selection ring is generic blue

ring-blue-500 ignores the brand indigo, breaking colour cohesion.

No empty/all-healthy state

A fleet with zero alerts shows an undifferentiated grid rather than a reassuring "all healthy" summary.

2 Enterprise recommendations

P1
Calm alerting: keep the card neutral, add a coloured left rail + badge; reserve fills for the metric that breached.
P1
Labelled metric bars with value, unit and a threshold tick.
P2
Brand-aligned selection and consistent chart palette.
P2
Health summary header (n healthy / n at-risk) with a filter to "show alerts only".

Groups

Manage static and dynamic node groups — create with a JSON predicate, bulk-delete, paginate. Groups drive credential inheritance and targeting.

1 Current-state critique

Raw JSON predicate textarea

Dynamic groups require hand-editing {"and": []} — error-prone and intimidating with no validation or builder.

Inline create form pushes content

Toggling showForm expands the page rather than using a focused dialog/drawer.

Bulk-delete lacks a sticky action bar

Selection state exists but the destructive action isn't clearly gated or summarized.

Static vs dynamic not visually distinct

Group type carries real behavioural weight but isn't badged.

2 Enterprise recommendations

P1
Visual predicate builder (key/op/value rows) with live match-count preview; JSON as an "advanced" escape hatch.
P1
Selection action bar that docks at the bottom with count + destructive confirm.
P2
Type badges (static/dynamic) and member-count chips on each group.
P2
Create in a drawer, not an inline expander.
