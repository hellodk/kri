The Problem

"New features kept
breaking old ones"§

kri started shipping fast. Too fast. Without a structured testing strategy, every sprint risked silent regressions — the fleet API would drift from the frontend, a new Ansible runner would clobber existing node state.

The Testing Pyramid

Four layers, one confident deploy§

Each layer has a clear mandate and a clear boundary. Slower tests live higher; faster tests live lower. The pyramid keeps CI fast without sacrificing coverage.

112 tests

Unit — Green foundation

Pure Python functions, zero I/O. Schema validators, fleet state calculators, Salt key parsers. Runs in under 3 seconds. The developer's inner loop.

95 tests

Integration — Real dependencies

PostgreSQL via pytest fixtures, FastAPI test client, Salt API mocks. Exercises the full request-response cycle for every endpoint.

Schema drift = P0

Contract — Pydantic ↔ TypeScript

Any field added to a Pydantic response model must have a matching TypeScript interface. Drift caught in CI, not in production.

User journeys

E2E — Playwright acceptance

Bootstrap a node, run an Ansible playbook, delete a group. Acceptance criteria as code, running in a real browser against a staging fleet.

CI Pipeline

From PR to merge in minutes§

GitHub Actions orchestrates a sequential gate: a failing step blocks the merge. No flaky green CIs — each job has a clear ownership contract.

Contract Testing

The silent killer: schema drift§

The backend speaks Pydantic; the frontend speaks TypeScript. Without enforcement, a renamed field on either side silently breaks the other. We treat schema drift as a P0 incident.

schemas/node.py
class NodeResponse(BaseModel): id: str minion_id: str status: NodeStatus group_id: Optional[str] ip_address: str # ← added serial_number: str # ← added
DRIFT
⟷
types/node.ts
interface NodeResponse { id: string; minionId: string; status: NodeStatus; groupId: string | null; // ip_address missing! // serial_number missing! }
schemas/node.py
class NodeResponse(BaseModel): id: str minion_id: str status: NodeStatus group_id: Optional[str] ip_address: str serial_number: str
IN SYNC
⟷
types/node.ts
interface NodeResponse { id: string; minionId: string; status: NodeStatus; groupId: string | null; ipAddress: string; serialNumber: string; }

The contract check runs as part of the PR review checklist and is enforced by a CI lint step that diffs field names between the Pydantic export and the TypeScript interface file. If fields don't match, the step exits non-zero.

What's next

Pushing the pyramid further§

The foundation is solid. Now we raise the ceiling — catching entire classes of bugs that unit tests can't see by construction.

Mutation Testing

Run mutmut against the unit suite to verify tests actually catch bugs — not just execute lines. A green test that passes when the code is deliberately broken is worthless.

Property-Based Tests

Hypothesis-driven testing for the fleet state machine. Generate hundreds of random node states and verify invariants hold — especially around group membership and Salt key transitions.

E2E in CI

Playwright tests currently run locally against a dev fleet. Next: spin up a containerised kri stack in GitHub Actions and run the full acceptance suite on every PR against master.
