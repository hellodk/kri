Deployment

Where to deploy kri

One Docker Compose stack on a laptop, NUC, or rack server — manages macOS and Linux nodes alike via SSH.

Component-wise — deploy/docker-compose.yml

Host options

Laptop — dev / demo · NUC — small lab · Rack server — production control plane

salt-master: Docker vs native

Docker — convenient for development (included in Compose). Native — recommended for production on a dedicated fleet node; point the API via .env.docker.

Celery queues

default · maintenance · drift · sbom — long-running work offloaded from the API.

docker compose -f deploy/docker-compose.yml up -d

SaltStack

Salt master + minion bootstrap

One-click onboarding: node picker discovers the target, installs the Salt minion over SSH, accepts keys, and joins the fleet — no manual setup.

Salt Master

Issues states via ZeroMQ (:4505 publish, :4506 request). Tracks accepted and pending minion keys in the UI.

Salt Minion (Auto-Installed)

Installed automatically during bootstrap on macOS 12+ or Linux. Grains feed drift engine and package visibility.

+ Ansible Playbooks

Same UI for Salt states and Ansible playbooks — unified run pipeline with live stdout streaming.

Compliance

Drift, packages & licensing

Every node scored against a baseline; installed packages visible from grains and SBOM scans; license risks surfaced via Trivy pipeline.

Drift engine — snapshot → diff → score

Installed Packages

Per-node package list from Salt grains (pkgs, brew_pkgs). Fleet-wide common-packages API from latest SBOM scans.

SBOM / Trivy Pipeline

CycloneDX SBOM ingested via Celery sbom queue. Trivy security scanning. Components indexed per node.

License Policy

Configurable license_policy (permissive / strict). Security dashboard aggregates license risks and vulnerability findings per node.
