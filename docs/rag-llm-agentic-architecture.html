RAG / Embeddings — Ingest, Store, Retrieve
kri embeds four source types into pgvector and retrieves relevant chunks using Hybrid BM25 + Vector search fused by Reciprocal Rank Fusion (RRF). Every chunk carries a [src: …] provenance tag so the LLM can cite its source. Reindexing is Celery-beat scheduled on the maintenance queue.
RAG Ingest → Embed → Store → Retrieve Pipeline — Animated

Four Source Types, Four Chunkers

💻
chunk_node()
One node = one chunk (profile card). Fields: hostname, node_id, IP, status, group, OS, last_seen. Re-embeds on registration, status change, group change. IP redacted when include_ips=False — same privacy gate as chat context.
📋
chunk_playbook()
One play = one chunk. Captures play name, target hosts, and the list of task names from the YAML. Source ID is path:play_N. Invalid YAML returns empty list silently.
⚙️
chunk_salt_state()
One top-level state ID = one chunk. SLS files are YAML; each root key is a state ID. Body includes path, state ID, and up to 400 chars of the declaration. Source ID is path:state_id.
📊
chunk_drift_record()
One drift report = one chunk. Captures node hostname, timestamp, drift score, and up to 10 entries each of missing, extra, and mismatched packages. Source ID is drift:uuid.

Embedding: nomic-embed-text-v1.5

1
Task Prefix Application
search_document: prepended at ingest; search_query: prepended at query time. This asymmetric prefix is required by nomic-embed-text-v1.5 for optimal retrieval — skipping it degrades recall.
2
Batched POST to /v1/embeddings
64 texts per batch, up to 3 retries with exponential backoff (2s, 4s, 8s) on transport errors. Large reindexes never 413 or time out.
3
Dimension Validation
Every vector is checked against Vector(768) — the configured column width. A wrong model or endpoint raises EmbeddingDimensionError immediately. No silent corruption.
4
True Upsert + Orphan Sweep
plan_upsert(): delete rows whose source_id changed hash, then insert fresh. plan_sweep(): delete rows whose source no longer exists (node deleted, playbook removed). The index never accumulates stale embeddings.

Hybrid Retrieval: BM25 + Vector → RRF Fusion

BM25 (Postgres FTS)

Full-text search over chunk_text using PostgreSQL's tsvector/tsquery. Excellent at matching exact hostnames, package names, and technical terms that embedding models may treat as semantically similar when they are not.

Vector Cosine Similarity

pgvector HNSW index (migration 045) over the 768-dim nomic vectors. Catches semantic matches — "node is down" matches "offline status" — that BM25 misses. The search_query: prefix ensures the query embedding aligns with the ingestion-time search_document: embedding.

Reciprocal Rank Fusion (k=60)

Each candidate scores 1/(60 + rank) from each ranked list. Scores are summed and candidates sorted descending. Deduplicates IDs that appear in both lists. The combined ranking reliably outperforms either signal alone, especially on short, ambiguous fleet queries.

# RRF pseudocode from embedding_svc.py
for ranked_list in [bm25_ids, vector_ids]:
    for rank, item_id in enumerate(ranked_list, start=1):
        scores[item_id] += 1.0 / (k + rank)  # k=60
return sorted(scores, key=lambda x: -scores[x])  # descending
Provenance tags are non-negotiable. Every chunk text begins with [src: type/id] (e.g. [src: node/mm2], [src: drift:abc123]). The LLM is instructed to cite these tags in its answer. Without them, there is no way to audit which retrieved chunk drove a claim.

LLM Assistant — Context Assembly & Multi-Model Routing
Every chat turn assembles a grounded system prompt from four layers — Fleet Snapshot, Node Records, RAG chunks, and pinned Grounding Rules — then routes to the configured model via OpenAI-compat SSE streaming or the native Anthropic SDK. Robustness mechanisms prevent the 500 on bad node data and surface actionable errors from endpoint failures.
Query → Context Assembly → Model → Grounded Answer — Animated

Grounding Rules — Why They Come Last

The system prompt always ends with the ## Rules section. This is intentional: when a small-context endpoint forces truncation, _truncate_system_prompt() drops the middle (RAG chunks / node records) but always preserves the head and tail. The grounding rules survive even when everything else is cut.

Key rules verbatim from the code:
· Node Records are the LIVE, AUTHORITATIVE inventory — source of truth.
· A node's hostname IS its name, even if it looks like an IP.
· Never tell the operator to "check the kri UI" for data already in context.
· Never claim to have executed a command or performed a live action.

Robustness Mechanisms

🛡️
_sanitize_cell()
Coerces non-str values (IPv4Address, datetime, int, None) to str before building the Markdown node table. Fixed a 500 where node.ip arrived as ipaddress.IPv4Address and .replace() raised AttributeError on every chat query (#633).
⚠️
_describe_http_error()
Surfaces the endpoint body (up to 300 chars) in the error message. A 404 adds the hint: "the configured model is not loaded — pick an available model in Settings → LLM." Auth errors say "check the API key."
🔄
Graceful Context Degradation
If context assembly fails (DB unreachable, schema error) the assistant falls back to a minimal prompt and responds. It never 500s the chat endpoint due to a context-building failure.
🧪
_validate_response()
Detects common small-model failures: response shorter than 5 chars, echoing the system prompt, and chat-template artifacts (<|im_start|> etc.). Returns a clean error message instead of surfacing garbage to the operator.

Multi-Model Routing + Auto Health Probing (#636)

kri supports any OpenAI-compatible endpoint (vLLM, Ollama, LM Studio, exo, Groq, Mistral, Together) plus Anthropic's native SDK. Routing is based on the endpoint configured as default, with per-endpoint capability detection to handle provider-specific quirks.

OpenAI-compat (SSE)

call_openai_compat() — streaming /v1/chat/completions. Handles per-chunk read timeout (30s silence = abort), thinking-model <think> block stripping, echo detection, and chat-template artifact removal. Stop tokens omitted for thinking models.

Anthropic Native SDK

call_anthropic() — uses anthropic.AsyncAnthropic with messages.create(). History passed directly. Returns (content, input_tokens, output_tokens) matching the OpenAI-compat signature so the router is provider-agnostic.

Local exo Models

exo serves local Apple Silicon models (Qwen3, DeepSeek, GLM) via OpenAI-compat at 192.168.1.23:52415. The normalize_openai_base_url() helper strips trailing /v1 to prevent doubled-prefix bugs (#272). No Tailscale relay — LAN-direct always.

Intent Classification

Intent is classified before context assembly and selects the task addendum appended to the system prompt. The addendum tells the model how to frame its response.

History Budget

The last 10 conversation turns are included in the messages array (both OpenAI-compat and Anthropic). This is a pragmatic cap: enough for multi-turn diagnosis sessions, cheap enough that even a 4k-context model can accommodate it.

Context length awareness: call_openai_compat() accepts model_context_length and clamps max_tokens to the model's window. The system prompt budget is (ctx − max_tokens) × 4 chars, ensuring the output region is always reserved.

IP redaction: when include_ips=False is set in platform settings, every IPv4 address in the assembled context is replaced with [REDACTED_IP] before the prompt leaves the backend. Same gate applies at embed time.
Agentic Control — Tool-Calling Loop + Safety Stack
kri's agentic layer lets the LLM propose actions against the fleet. The LLM is an untrusted actor — it never executes directly. A layered safety stack intercepts every tool call: denylist, dry-run, operator confirmation, then admin-inbox approval of the verbatim resolved action. READ tools auto-run from cached DB data; WRITE tools require the full two-layer human approval.

Backend-Agnostic Tool Adapters

The LLM is an untrusted actor that may use any of three tool-call formats. kri normalizes them all to (function, args, node) before routing.

🔧
Native tool_calls
OpenAI / vLLM / Ollama format — structured JSON in the tool_calls field of the completion. Per-endpoint capability detection determines if the endpoint supports this format.
🤖
Anthropic tool_use
Claude's native format — tool invocations appear as tool_use content blocks in the response. The Anthropic SDK route handles this natively.
📄
JSON / Content Fallback
exo emits Llama-format tool calls as <|python_tag|>{json} inside the content string. kri parses and normalizes this universally — any serving stack (exo, mlx, vLLM, llama.cpp) that emits JSON-in-content is handled.

Protected Targets — Hardcoded Denylist

These targets cannot be stopped, suspended, or disabled remotely under any circumstance. The check happens at the validation layer before the approval gate is even reached — a 403 is returned immediately.

salt-minion salt-master sshd exo launchd kernel_task
windowserver syslogd networkd configd securityd trustd opendirectoryd powerd mdnsresponder
process_kill (SIGKILL) is in FORBIDDEN — blocked entirely, not gated. No approval flow can authorize it. SIGTERM (15), SIGSTOP (17), and SIGCONT (19) are the only signals available, and only for non-protected targets.

READ Tools — Auto-Run from Cache

READ tools query cached DB data — no network call to the node, no Salt dispatch. They execute in the same request cycle and return results directly into the LLM's next context window.

Runaway Safety + Feature Flag

1
Rate Limiting
Node action endpoints are rate-limited (#616). A runaway agent loop cannot flood the approval system or the Salt API.
2
Max Steps / Wall / Tokens
Per-session caps on loop iterations, wall-clock time, and token consumption. An agent that loops without progress is aborted automatically.
3
Redis Inference Semaphore
At most N concurrent agent sessions per node to prevent parallel conflicting actions. Redis semaphore released on session completion or timeout.
4
Feature Flag
The entire agentic subsystem is guarded by a feature flag in platform settings. Disabled by default — operators opt in explicitly.

Durable State Machine: AgentSession / AgentAction

Agent sessions and their constituent actions are persisted off the async event loop. This means:

Session Durability

AgentSession records track the full multi-turn loop. A session survives a worker restart — the loop can be resumed or inspected after a crash.

Action Immutability

Once an AgentAction row is committed with its resolved (function, args, node), it cannot be modified. The admin approves this exact record — not a mutable prose description.

PendingAction TTL

Approval tokens expire after 15 minutes. An approval not acted on becomes expired. The operator must re-request a fresh action — preventing stale approvals from executing later.

# PendingAction states: pending → approved → executed
#                      pending → rejected
#                      pending → expired (beat task sweeps every minute)
